# Caducidad del Historial del Cliente de Ejecución

Los clientes de Ejecución pueden descartar cuerpos de bloque y recibos antiguos para que los datos de la cadena mantengan un tamaño manejable. La configuración **Pruning Mode** del Smartnode (Execution Client → Pruning Mode) controla este comportamiento.

**Rolling History Expiry** es la opción predeterminada. Nethermind, Besu, Reth y Erigon descartan cuerpos y recibos de más de un año de antigüedad aproximadamente. Geth todavía no implementa ese modo y en su lugar utiliza la caducidad del historial anterior a Prague.

Las otras opciones:

- **History Expiry** — descarta únicamente los cuerpos y recibos _pre-merge_ (caducidad parcial [EIP-4444](https://eips.ethereum.org/EIPS/eip-4444)). Erigon no admite la caducidad exclusiva de pre-merge.
- **Full node** — conserva los datos habituales de un nodo completo, incluidos cuerpos y recibos. El modo de nodo completo de Erigon conserva los recibos.
- **Archive** — conserva el historial y el estado histórico (lo que requiere mucho más disco).

No dudes en leer esta descripción general de la caducidad parcial del historial: https://blog.ethereum.org/2025/07/08/partial-history-exp

::: tip NOTA

Las instalaciones nuevas ya utilizan Rolling History Expiry. Si anteriormente elegiste un Pruning Mode diferente, selecciona **Rolling History Expiry** en la TUI y **resincroniza** el cliente de Ejecución para que surta efecto.

- **Nethermind, Reth y Erigon** — resincroniza después de cambiar el modo (`rocketpool service resync-eth1`).
- **Geth** — poda con `rocketpool service prune-eth1` o resincroniza; Geth sigue utilizando la caducidad anterior a Prague en lugar de la caducidad rodante de un año.
- **Besu** — permanece en línea.

:::

Los siguientes pasos para eliminar el historial pre-merge son solo para nodos en modo Docker. Si estás utilizando un cliente externo en
modo Híbrido o modo Nativo, consulta la documentación proporcionada por tu cliente de Ejecución.

Comienza abriendo el Administrador de Configuración:

```shell
rocketpool service config
```

Para cambiar el modo de poda del Cliente de Ejecución, ve al menú `Execution Client (ETH1)` y selecciona la configuración `History Expiry` en el menú desplegable de `Pruning Mode`

Elige **Rolling History Expiry** a menos que tengas una razón para conservar más historial.

![](../images/tui-history-expiry.png)

Después de haber realizado la selección, presiona `escape` para volver al menú principal, luego presiona `tab` para resaltar el botón `Review Changes and Save`. Presiona
la tecla `enter` para continuar. Se te presentará un menú para previsualizar los cambios en la configuración de tu cliente de Ejecución.

![](../images/tui-review-history-expiry.png)

Presiona la tecla `enter` en `Save Settings` para guardar y salir del Administrador de Configuración, luego ingresa `y` para reiniciar tu contenedor `rocketpool_eth1`.

```shell
Your changes have been saved!
The following containers must be restarted for the changes to take effect:
	rocketpool_eth1
Would you like to restart them automatically now? [y/n]
```

A partir de este punto, los pasos difieren según el cliente de Ejecución que estés usando:
