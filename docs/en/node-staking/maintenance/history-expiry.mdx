# Execution Client History Expiry

Execution clients can drop old block bodies and receipts so the chain data stays a manageable size. The Smartnode **Pruning Mode** setting (Execution Client → Pruning Mode) controls this.

**Rolling History Expiry** is the default. Nethermind, Besu, Reth, and Erigon drop bodies and receipts older than about one year. Geth does not implement that mode yet and uses pre-Prague history expiry instead.

The other choices:

- **History Expiry** — drop *pre-merge* bodies and receipts only (partial [EIP-4444](https://eips.ethereum.org/EIPS/eip-4444) expiry). Erigon does not support pre-merge-only expiry.
- **Full node** — keep the usual full-node data, including bodies and receipts. Erigon full-node mode keeps receipts.
- **Archive** — keep history and historical state (which requires much more disk).

Feel free to read this overview of partial history expiry: https://blog.ethereum.org/2025/07/08/partial-history-exp

::: tip NOTE

New installs already use Rolling History Expiry. If you previously picked a different Pruning Mode, select **Rolling History Expiry** in the TUI and **resync** the Execution client for it to take effect.

- **Nethermind, Reth and Erigon** — resync after changing the mode (`rocketpool service resync-eth1`).
- **Geth** — prune with `rocketpool service prune-eth1` or resync; Geth still uses pre-Prague expiry rather than one-year rolling expiry.
- **Besu** — stays online.

:::

The following steps to remove pre-merge history are for Docker mode nodes only. If you are using an external client in Hybrid
mode or Native mode, please refer to the documentation provided by your Execution client.

Start by opening the Settings Manager:

```shell
rocketpool service config
```

To change the Execution Client pruning mode, go to the `Execution Client (ETH1)` menu and select the `History Expiry` setting in the dropdown menu for `Pruning Mode`

Pick **Rolling History Expiry** unless you have a reason to keep more history.

![](../images/tui-history-expiry.png)

After you've made the selection, press `escape` to return to the main menu, then press `tab` to highlight the `Review Changes and Save` button. Press
the `enter` key to continue. You'll be presented with a menu to preview the changes to your Execution client settings.

![](../images/tui-review-history-expiry.png)

Press the `enter` key on `Save Settings` to save and exit the Settings Manager, then enter `y` to restart your `rocketpool_eth1` container.

```shell
Your changes have been saved!
The following containers must be restarted for the changes to take effect:
	rocketpool_eth1
Would you like to restart them automatically now? [y/n]
```

From this point on, the steps differ depending on which Execution client you're using:
