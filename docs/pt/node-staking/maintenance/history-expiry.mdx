# Expiração do Histórico do Cliente de Execução

Os clientes de Execução podem descartar corpos de bloco e recibos antigos para que os dados da cadeia mantenham um tamanho gerenciável. A configuração **Pruning Mode** do Smartnode (Execution Client → Pruning Mode) controla esse comportamento.

**Rolling History Expiry** é o padrão. Nethermind, Besu, Reth e Erigon descartam corpos e recibos com mais de aproximadamente um ano. O Geth ainda não implementa esse modo e usa a expiração de histórico anterior ao Prague.

As outras opções:

- **History Expiry** — descarta apenas os corpos e recibos _pré-merge_ (expiração parcial [EIP-4444](https://eips.ethereum.org/EIPS/eip-4444)). O Erigon não suporta a expiração exclusivamente pré-merge.
- **Full node** — mantém os dados usuais de um nó completo, incluindo corpos e recibos. O modo de nó completo do Erigon mantém os recibos.
- **Archive** — mantém o histórico e o estado histórico (o que exige muito mais disco).

Fique à vontade para ler esta visão geral sobre expiração parcial de histórico: https://blog.ethereum.org/2025/07/08/partial-history-exp

::: tip NOTA

Instalações novas já usam Rolling History Expiry. Se você escolheu anteriormente um Pruning Mode diferente, selecione **Rolling History Expiry** na TUI e **ressincronize** o cliente de Execução para que a mudança tenha efeito.

- **Nethermind, Reth e Erigon** — ressincronize após alterar o modo (`rocketpool service resync-eth1`).
- **Geth** — faça a poda com `rocketpool service prune-eth1` ou ressincronize; o Geth ainda usa a expiração anterior ao Prague em vez da expiração rolante de um ano.
- **Besu** — permanece online.

:::

As etapas a seguir para remover o histórico pré-merge são apenas para nós no modo Docker. Se você estiver usando um cliente externo no modo
Hybrid ou modo Native, consulte a documentação fornecida pelo seu cliente de Execução.

Comece abrindo o Gerenciador de Configurações:

```shell
rocketpool service config
```

Para alterar o modo de poda do Cliente de Execução, vá ao menu `Execution Client (ETH1)` e selecione a configuração `History Expiry` no menu suspenso para `Pruning Mode`

Escolha **Rolling History Expiry** a menos que você tenha um motivo para manter mais histórico.

![](../images/tui-history-expiry.png)

Depois de fazer a seleção, pressione `escape` para retornar ao menu principal, depois pressione `tab` para destacar o botão `Review Changes and Save`. Pressione
a tecla `enter` para continuar. Você verá um menu para visualizar as alterações nas configurações do seu cliente de Execução.

![](../images/tui-review-history-expiry.png)

Pressione a tecla `enter` em `Save Settings` para salvar e sair do Gerenciador de Configurações, depois digite `y` para reiniciar seu contêiner `rocketpool_eth1`.

```shell
Your changes have been saved!
The following containers must be restarted for the changes to take effect:
	rocketpool_eth1
Would you like to restart them automatically now? [y/n]
```

A partir deste ponto, as etapas diferem dependendo de qual cliente de Execução você está usando:
