# Commit-Boost

O Commit-Boost é um sidecar de validador de código aberto e mantido pela comunidade, que serve como alternativa ao MEV-Boost para lidar com a Separação Proponente-Construtor (PBS).
Além da construção de blocos, o Commit-Boost também suporta protocolos de compromissos do proponente, como pré-confirmações e listas de inclusão.
Atualmente, o Smart Node executa apenas o módulo PBS (construção de blocos) do Commit-Boost, então esses protocolos adicionais ainda não estão disponíveis pelo Smart Node.
Se você é novo em MEV e PBS, recomendamos ler primeiro a página [MEV, MEV-Boost e Recompensas MEV](./mev) para contexto.

## O que é o Commit-Boost?

O Commit-Boost é um substituto direto do MEV-Boost com recursos adicionais. Seu principal objetivo é padronizar a comunicação entre validadores Ethereum e protocolos de terceiros.

- Usa a mesma Builder API do MEV-Boost (porta padrão 18550), então seu Beacon Node se comunica com ele da mesma forma que com o MEV-Boost.
- Conecta-se aos relays de MEV e cuida da construção de blocos, assim como o MEV-Boost.
- Suporta um sistema modular de plugins para os futuros protocolos de compromissos.
- Para desenvolvedores, oferece uma única API para interagir com validadores.

O Commit-Boost é de [código aberto](https://github.com/Commit-Boost/commit-boost-client) e foi [auditado](https://github.com/Commit-Boost/commit-boost-client/blob/main/audit/Sigma_Prime_Commit_Boost_Client_Security_Assessment_Report_v2_0.pdf) pela Sigma Prime em dezembro de 2024.

## Commit-Boost vs MEV-Boost

Tanto o Commit-Boost quanto o MEV-Boost lidam com o PBS usando o mercado de construtores e a infraestrutura de relays de MEV. Veja como eles diferem:

| Recurso                          | MEV-Boost   | Commit-Boost                                                                           |
| -------------------------------- | ----------- | -------------------------------------------------------------------------------------- |
| **Finalidade**                   | Somente PBS | PBS + plataforma extensível e modular                                                  |
| **Mantenedor**                   | Flashbots   | Comunidade / equipe do Commit-Boost                                                    |
| **Protocolos futuros**           | Estático    | Sistema de plugins para protocolos de terceiros (ainda não disponível pelo Smart Node) |
| **Relays disponíveis (mainnet)** | 8 relays    | 5 relays (somente com filtragem OFAC)                                                  |

Do ponto de vista do Smart Node, ambos se conectam ao seu Beacon Node de forma idêntica. O Commit-Boost é voltado para o futuro, à medida que o Ethereum adiciona novos recursos de compromissos do proponente, como pré-confirmações.

:::tip NOTA
Você não pode executar o MEV-Boost e o Commit-Boost ao mesmo tempo. O Smart Node impõe isso ao salvar sua configuração na TUI.
:::

## Relays disponíveis

Estes são os relays disponíveis no Commit-Boost:

| Nome                                                                                                         | Regulação                   | Redes           | Tipos de MEV   |
| ------------------------------------------------------------------------------------------------------------ | --------------------------- | --------------- | -------------- |
| [Flashbots](https://boost.flashbots.net/)                                                                    | Cumpre as sanções da OFAC\* | Mainnet, Hoodi  | Todos os tipos |
| [bloXroute Regulated](https://docs.bloxroute.com/eth/block-builders-and-validators/mev-relay-for-validators) | Cumpre as sanções da OFAC\* | Mainnet, Hoodi  | Todos os tipos |
| [Titan Regional](https://docs.titanrelay.xyz/)                                                               | Cumpre as sanções da OFAC\* | Somente mainnet | Todos os tipos |
| [Ultra Sound Filtered](https://relay-filtered.ultrasound.money/)                                             | Cumpre as sanções da OFAC\* | Somente mainnet | Todos os tipos |
| BTCS OFAC+                                                                                                   | Cumpre as sanções da OFAC\* | Somente mainnet | Todos os tipos |
| [AESTUS](https://aestus.live/)                                                                               | Não regulado                | Somente Hoodi   | Todos os tipos |
| [Titan Global](https://docs.titanrelay.xyz/)                                                                 | Não regulado                | Somente Hoodi   | Todos os tipos |

:::warning NOTA
\*Os relays que cumprem as sanções da OFAC seguem a lista negra de endereços mantida pelo Office of Foreign Assets Control (OFAC) dos Estados Unidos.
**Recomendamos fortemente** que você leia mais sobre as sanções da OFAC e a censura na rede, e tome uma decisão cuidadosamente informada sobre quais relays você se sente confortável em usar.

Mais informações podem ser encontradas na [página de MEV](./mev#construtores-de-blocos-e-relays).
:::

:::warning IMPORTANTE
Na mainnet, o Commit-Boost suporta **menos relays** que o MEV-Boost no Smart Node. Especificamente, o Commit-Boost na mainnet **não** inclui:

- Ultra Sound (sem filtragem)
- Aestus
- Titan Global (sem filtragem)

Todos os relays disponíveis no Commit-Boost na mainnet são versões reguladas/filtradas que cumprem as sanções da OFAC. Se você precisa de acesso a relays não regulados, deve continuar usando o MEV-Boost em vez do Commit-Boost.
:::

## Recompensas e APY

O Commit-Boost oferece recompensas semelhantes às do MEV-Boost.
Como o Commit-Boost suporta apenas relays regulados na mainnet, você pode ver recompensas MEV um pouco diferentes em comparação com o MEV-Boost se antes usava relays não regulados.

No futuro, protocolos de compromissos do proponente, como pré-confirmações e listas de inclusão, poderão adicionar rendimento extra além das recompensas MEV padrão.

      **Container Tag**: a tag da imagem Docker do Commit-Boost. O Smart Node define o valor padrão e o atualiza a cada versão. Você pode alterá-la manualmente se uma nova versão for lançada antes da atualização do Smart Node.

## Verificando os logs e o funcionamento

Depois de habilitar o Commit-Boost, você pode verificar se ele está funcionando corretamente consultando os logs:

```bash
rocketpool service logs commit-boost
```

Você deve ver uma saída de log semelhante a esta, mostrando registros de validadores bem-sucedidos nos relays:

O que procurar nos logs:

- Entradas `new request` mostrando seu Validator Client se conectando ao Commit-Boost
- `register validator successful`, confirmando que seus validadores estão registrados nos relays
- Respostas `200 OK`, indicando comunicação bem-sucedida

Você também pode verificar se o Commit-Boost está em execução com:

```bash
rocketpool service version
```

Perto do final da saída, você deve ver:

```
MEV-Boost client: Disabled
Commit-Boost client: Enabled (Local Mode)
	Image: ghcr.io/commit-boost/commit-boost:<version>
```

Se você usa uma instância gerenciada externamente, será exibido `Enabled (External Mode)`.

## Trocando do MEV-Boost para o Commit-Boost

Trocar do MEV-Boost para o Commit-Boost é simples:

1. Execute `rocketpool service config`
2. Selecione a categoria **ePBS**, depois **MEV-Boost**, e desmarque `Enable MEV-Boost`
3. Volte à categoria **ePBS**, selecione **Commit-Boost** e marque `Enable Commit-Boost`
4. Configure suas preferências de relays
5. Salve e saia

O Smart Node cuidará do resto. Seu Beacon Node será atualizado automaticamente para usar o Commit-Boost em vez do MEV-Boost.

:::tip NOTA
A troca reinicia seu Beacon Node, então seus validadores podem perder uma ou duas atestações enquanto ele volta a funcionar. Evite fazer a troca logo antes de uma proposta agendada.
:::
