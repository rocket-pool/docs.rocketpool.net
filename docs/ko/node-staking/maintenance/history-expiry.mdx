# Execution 클라이언트 히스토리 만료

Execution 클라이언트는 오래된 블록 바디와 영수증을 삭제하여 체인 데이터를 관리 가능한 크기로 유지할 수 있습니다. Smartnode의 **Pruning Mode** 설정(Execution Client → Pruning Mode)이 이를 제어합니다.

**Rolling History Expiry**가 기본값입니다. Nethermind, Besu, Reth 및 Erigon은 약 1년보다 오래된 바디와 영수증을 삭제합니다. Geth는 아직 이 모드를 구현하지 않았으며 대신 Prague 이전 히스토리 만료를 사용합니다.

기타 선택지:

- **History Expiry** — _pre-merge_ 바디와 영수증만 삭제합니다(부분 [EIP-4444](https://eips.ethereum.org/EIPS/eip-4444) 만료). Erigon은 pre-merge 전용 만료를 지원하지 않습니다.
- **Full node** — 바디와 영수증을 포함한 일반적인 풀 노드 데이터를 유지합니다. Erigon의 풀 노드 모드는 영수증을 유지합니다.
- **Archive** — 히스토리와 과거 상태를 유지합니다(훨씬 더 많은 디스크가 필요합니다).

부분 히스토리 만료에 대한 개요는 여기에서 확인하세요: https://blog.ethereum.org/2025/07/08/partial-history-exp

::: tip 참고

새로 설치한 노드는 이미 Rolling History Expiry를 사용합니다. 이전에 다른 Pruning Mode를 선택했다면, TUI에서 **Rolling History Expiry**를 선택하고 Execution 클라이언트를 **재동기화**해야 적용됩니다.

- **Nethermind, Reth 및 Erigon** — 모드를 변경한 후 재동기화하세요(`rocketpool service resync-eth1`).
- **Geth** — `rocketpool service prune-eth1`으로 가지치기하거나 재동기화하세요. Geth는 1년 롤링 만료가 아닌 Prague 이전 만료를 계속 사용합니다.
- **Besu** — 온라인 상태를 유지합니다.

:::

다음 pre-merge 히스토리 제거 단계는 Docker 모드 노드에만 해당됩니다. Hybrid 모드 또는 Native 모드에서 외부 클라이언트를 사용하는 경우 Execution 클라이언트에서 제공하는 문서를 참조하세요.

먼저 Settings Manager를 엽니다:

```shell
rocketpool service config
```

Execution Client 가지치기 모드를 변경하려면 `Execution Client (ETH1)` 메뉴로 이동하여 `Pruning Mode` 드롭다운 메뉴에서 `History Expiry` 설정을 선택합니다

더 많은 히스토리를 유지할 이유가 없다면 **Rolling History Expiry**를 선택하세요.

![](../images/tui-history-expiry.png)

선택한 후 `escape`를 눌러 메인 메뉴로 돌아간 다음 `tab`을 눌러 `Review Changes and Save` 버튼을 강조 표시합니다. `enter` 키를 눌러 계속합니다. Execution 클라이언트 설정 변경 사항을 미리 볼 수 있는 메뉴가 표시됩니다.

![](../images/tui-review-history-expiry.png)

`Save Settings`에서 `enter` 키를 눌러 Settings Manager를 저장하고 종료한 다음 `y`를 입력하여 `rocketpool_eth1` 컨테이너를 재시작합니다.

```shell
Your changes have been saved!
The following containers must be restarted for the changes to take effect:
	rocketpool_eth1
Would you like to restart them automatically now? [y/n]
```

이 시점부터 단계는 사용 중인 Execution 클라이언트에 따라 다릅니다:
