# Execution Client 정리하기

::: tip 참고
이 페이지는 `geth` 및 `nethermind`를 위한 **오프라인 / 온라인 가지치기** 경로입니다(`rocketpool service prune-eth1`).

디스크 사용량을 관리하는 일반적인 방법은 **Rolling History Expiry**(기본 Pruning Mode)입니다. Nethermind, Besu, Reth 및 Erigon은 약 1년보다 오래된 바디와 영수증을 삭제하며, Geth는 대신 Prague 이전 히스토리 만료를 사용합니다. [Execution 클라이언트 히스토리 만료](./maintenance/history-expiry)를 참조하세요.

:::

기본 Execution client로 `geth` 또는 `nethermind`를 사용하는 경우, 노드의 여유 디스크 공간이 시간이 지남에 따라 천천히 감소하는 것을 알 수 있습니다.
Execution client는 단연코 가장 큰 기여자입니다; `rocketpool service config` 중에 캐시에 할당한 RAM의 양에 따라 하루에 수 기가바이트의 속도로 증가할 수 있습니다!

이를 처리하기 위해 Execution client는 데이터베이스를 안전하게 스캔하고 정리하여 여유 공간을 회수할 수 있는 **정리(pruning)**라는 특수 기능을 제공합니다.
Geth 또는 Nethermind를 사용하는 모든 node operator는 결국 정리해야 합니다.

2TB SSD가 있는 경우 일반적으로 정리 라운드 사이에 몇 달 동안 지낼 수 있습니다.
1TB SSD 사용자의 경우 더 자주 정리해야 합니다.

[Grafana 대시보드](./grafana)가 활성화된 경우, 노드의 사용된 디스크 공간이 80%를 초과할 때 Execution client 정리를 고려하기 시작하는 것이 좋은 경험 법칙입니다.

정리할 시간이라고 판단되면 Smart Node에는 요청 시 정리할 수 있는 기능이 포함되어 있습니다.
작동 방식과 예상 사항을 알아보려면 아래를 읽어보십시오.

::: warning 참고
Execution client 정리는 Docker Mode에서만 가능합니다.

Hybrid mode의 외부 client 또는 Native mode와 같은 자체 Execution client를 사용하는 경우 Smart Node를 사용하여 Execution client를 정리할 수 없습니다.
수동으로 정리해야 합니다.
Execution client를 정리하는 방법을 알아보려면 Execution client의 문서를 참조하십시오.
:::

## Nethermind 2.0과 FlatDB

Smart Node v1.24.3부터 Smart Node는 **Nethermind 2.0**을 사용합니다. Nethermind 2.0은 새 데이터베이스를 **FlatDB**라는 형식으로 저장합니다.
FlatDB는 수동 상태 정리가 필요하지 않으며 지원하지도 않습니다. Nethermind 데이터베이스가 FlatDB를 사용하는 경우 `rocketpool service prune-eth1`이 전혀 필요하지 않습니다.

기존 Nethermind 데이터베이스는 변환되지 **않습니다**. 노드가 Nethermind 2.0 이전에 동기화되었다면 레거시 **Patricia** 데이터베이스를 계속 사용하며, 이 페이지에 설명된 대로 계속 정리할 수 있습니다.
FlatDB로 전환하는 유일한 방법은 `rocketpool service resync-eth1`로 Execution 클라이언트를 재동기화하는 것입니다.

::: warning 참고
재동기화하기 전에 [백업 노드를 설정](./fallback)하고 [제대로 작동하는지 테스트](./fallback#백업-클라이언트-테스트하기)하는 것을 고려하세요.
백업이 구성되어 있으면 기본 Execution 클라이언트가 재동기화되는 동안 Smart Node와 Consensus 클라이언트가 자동으로 백업으로 전환되고, 동기화가 완료되면 다시 돌아옵니다.
:::

### 사용 중인 데이터베이스 확인하기

다음을 실행하세요:

```shell
rocketpool service get-db-details
```

| 출력                                                                            | 의미                                                                 |
| ------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| `Nethermind is using FlatDB. Manual state pruning is not needed or supported.`  | 정리할 필요가 없습니다. 이 페이지의 나머지 내용은 해당되지 않습니다. |
| `Nethermind is using the legacy Patricia database. State pruning is supported.` | 디스크가 차기 시작하면 아래의 정리 단계를 따르세요.                  |
| `Nethermind has no persisted state database yet.`                               | Nethermind가 아직 상태를 기록하지 않았습니다(예: 재동기화 직후).     |

::: tip 참고
`get-db-details`를 사용하려면 Execution 클라이언트 컨테이너가 실행 중이어야 합니다.
이 명령은 데이터베이스 형식만 보고합니다. Archive 노드에서는 상태 정리가 지원된다고 표시될 수 있지만, Archive 노드는 정리할 수 없습니다.
:::

### RAM이 16 GiB 이하인 시스템의 FlatInTrie

Nethermind가 **RAM이 16 GiB 이하**인 머신에서 새 데이터베이스를 동기화하면, Smart Node는 메모리가 적은 시스템에 더 적합한 Nethermind의 **FlatInTrie** FlatDB 레이아웃을 선택합니다.
이 선택은 데이터베이스와 함께 저장되므로 재시작하거나 나중에 RAM을 추가해도 바뀌지 않습니다.
`rocketpool service resync-eth1`로 재동기화할 때만 초기화됩니다.

### 레거시 데이터베이스에만 적용되는 설정

`rocketpool service config`의 다음 Nethermind 설정은 레거시 Patricia 데이터베이스에만 영향을 미치며 FlatDB에서는 무시됩니다:

- In-Memory Pruning Cache Size
- Full Prune Memory Budget Size
- Prune threshold (MB)
- Full pruning parallelism

::: tip 참고
FlatDB는 **상태** 정리의 필요성을 없애줍니다. 노드가 보관하는 **기록**(블록 본문과 영수증)의 양은 바뀌지 않습니다.
이는 여전히 **Pruning Mode** 설정으로 제어됩니다. [Execution 클라이언트 기록 만료](./maintenance/history-expiry)를 참조하세요.
:::

## Geth를 Pebble v2로 마이그레이션하기

**Geth**를 실행 중이고 데이터베이스가 여전히 Pebble v1이라면, 다음 명령으로 제자리에서 마이그레이션할 수 있습니다:

```shell
rocketpool service migrate-geth
```

이 명령은 Geth를 종료하고 Pebble v1 → v2로 마이그레이션한 다음 다시 시작합니다. `prune-eth1`과는 **다르며**, 명령 이름은 **`migrate-geth`**입니다(`migrate-eth1`이 아닙니다).

::: warning 경고
마이그레이션이 진행되는 동안 Geth는 오프라인 상태입니다. [폴백 노드](./fallback)가 없으면 마이그레이션이 끝날 때까지 증명과 블록 제안을 놓치게 됩니다.
:::

프롬프트를 확인하거나 `--yes`를 전달하여 건너뛰세요. 진행 상황은 다음 명령으로 확인합니다:

```shell
rocketpool service logs eth1
```

마이그레이션이 완료될 때까지 컨테이너를 중단하지 마세요.
