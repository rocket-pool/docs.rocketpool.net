# Удаление истории Execution-клиента

Execution-клиенты могут удалять старые тела блоков и квитанции, чтобы данные цепочки оставались приемлемого размера. Этим управляет настройка Smartnode **Pruning Mode** (Execution Client → Pruning Mode).

**Rolling History Expiry** используется по умолчанию. Nethermind, Besu, Reth и Erigon удаляют тела блоков и квитанции старше примерно одного года. Geth пока не реализует этот режим и вместо него использует удаление истории до Prague.

Другие варианты:

- **History Expiry** — удаляет только тела блоков и квитанции _до слияния_ (частичное удаление по [EIP-4444](https://eips.ethereum.org/EIPS/eip-4444)). Erigon не поддерживает удаление только истории до слияния.
- **Full node** — сохраняет обычные данные полной ноды, включая тела блоков и квитанции. В режиме полной ноды Erigon сохраняет квитанции.
- **Archive** — сохраняет историю и историческое состояние (что требует значительно больше места на диске).

Ознакомьтесь с этим обзором частичного удаления истории: https://blog.ethereum.org/2025/07/08/partial-history-exp

::: tip ПРИМЕЧАНИЕ

Новые установки уже используют Rolling History Expiry. Если ранее вы выбрали другой Pruning Mode, выберите **Rolling History Expiry** в TUI и **повторно синхронизируйте** Execution-клиент, чтобы изменение вступило в силу.

- **Nethermind, Reth и Erigon** — выполните повторную синхронизацию после смены режима (`rocketpool service resync-eth1`).
- **Geth** — выполните обрезку с помощью `rocketpool service prune-eth1` или повторную синхронизацию; Geth по-прежнему использует удаление истории до Prague, а не годовое скользящее удаление.
- **Besu** — остаётся в сети.

:::

Следующие шаги по удалению истории до слияния предназначены только для нод в режиме Docker. Если вы используете внешний клиент в
гибридном режиме или нативном режиме, обратитесь к документации, предоставленной вашим Execution-клиентом.

Начните с открытия менеджера настроек:

```shell
rocketpool service config
```

Чтобы изменить режим обрезки Execution-клиента, перейдите в меню `Execution Client (ETH1)` и выберите настройку `History Expiry` в выпадающем меню `Pruning Mode`

Выбирайте **Rolling History Expiry**, если у вас нет причин хранить больше истории.

![](../images/tui-history-expiry.png)

После выбора нажмите `escape`, чтобы вернуться в главное меню, затем нажмите `tab`, чтобы выделить кнопку `Review Changes and Save`. Нажмите
клавишу `enter`, чтобы продолжить. Вам будет представлено меню для предварительного просмотра изменений в настройках вашего Execution-клиента.

![](../images/tui-review-history-expiry.png)

Нажмите клавишу `enter` на `Save Settings`, чтобы сохранить и выйти из менеджера настроек, затем введите `y`, чтобы перезапустить контейнер `rocketpool_eth1`.

```shell
Your changes have been saved!
The following containers must be restarted for the changes to take effect:
	rocketpool_eth1
Would you like to restart them automatically now? [y/n]
```

С этого момента шаги различаются в зависимости от того, какой Execution-клиент вы используете:
