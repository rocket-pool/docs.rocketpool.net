# Commit-Boost

Commit-Boost — это sidecar для валидаторов с открытым исходным кодом, развиваемый сообществом. Он служит альтернативой MEV-Boost для разделения ролей предлагающего и строителя блоков (Proposer-Builder Separation, PBS).
Помимо построения блоков, Commit-Boost также поддерживает протоколы обязательств предлагающего, такие как предподтверждения (preconfirmations) и списки включения (inclusion lists).
Сейчас Smart Node запускает только модуль PBS (построение блоков) Commit-Boost, поэтому эти дополнительные протоколы пока недоступны через Smart Node.
Если вы только знакомитесь с MEV и PBS, рекомендуем сначала прочитать страницу [MEV, MEV-Boost и награды MEV](./mev).

## Что такое Commit-Boost?

Commit-Boost — это прямая замена MEV-Boost с дополнительными возможностями. Его главная цель — стандартизировать взаимодействие между валидаторами Ethereum и сторонними протоколами.

- Использует тот же Builder API, что и MEV-Boost (порт по умолчанию 18550), поэтому ваш Beacon Node взаимодействует с ним так же, как с MEV-Boost.
- Подключается к MEV-релеям и отвечает за построение блоков, как и MEV-Boost.
- Поддерживает модульную систему плагинов для будущих протоколов обязательств.
- Для разработчиков предоставляет единый API для взаимодействия с валидаторами.

Commit-Boost имеет [открытый исходный код](https://github.com/Commit-Boost/commit-boost-client) и прошёл [аудит](https://github.com/Commit-Boost/commit-boost-client/blob/main/audit/Sigma_Prime_Commit_Boost_Client_Security_Assessment_Report_v2_0.pdf) Sigma Prime в декабре 2024 года.

## Commit-Boost и MEV-Boost

И Commit-Boost, и MEV-Boost реализуют PBS с помощью рынка строителей блоков и инфраструктуры MEV-релеев. Вот чем они различаются:

| Характеристика | MEV-Boost | Commit-Boost |
|---------|-----------|--------------|
| **Назначение** | Только PBS | PBS + расширяемая модульная платформа |
| **Разработчик** | Flashbots | Сообщество / команда Commit-Boost |
| **Будущие протоколы** | Нет | Система плагинов для сторонних протоколов (пока недоступна через Smart Node) |
| **Доступные релеи (mainnet)** | 8 релеев | 5 релеев (только с фильтрацией OFAC) |

С точки зрения Smart Node оба подключаются к вашему Beacon Node одинаково. Commit-Boost ориентирован на будущее, поскольку в Ethereum появляются новые функции обязательств предлагающего, например предподтверждения.

:::tip ПРИМЕЧАНИЕ
Нельзя одновременно запускать MEV-Boost и Commit-Boost. Smart Node проверяет это при сохранении конфигурации в TUI.
:::

## Доступные релеи

В Commit-Boost доступны следующие релеи:

| Название | Регулирование | Сети | Типы MEV |
|------|-----------|----------|-----------|
| [Flashbots](https://boost.flashbots.net/) | Соблюдает санкции OFAC* | Mainnet, Hoodi | Все типы |
| [bloXroute Regulated](https://docs.bloxroute.com/eth/block-builders-and-validators/mev-relay-for-validators) | Соблюдает санкции OFAC* | Mainnet, Hoodi | Все типы |
| [Titan Regional](https://docs.titanrelay.xyz/) | Соблюдает санкции OFAC* | Только mainnet | Все типы |
| [Ultra Sound Filtered](https://relay-filtered.ultrasound.money/) | Соблюдает санкции OFAC* | Только mainnet | Все типы |
| BTCS OFAC+ | Соблюдает санкции OFAC* | Только mainnet | Все типы |
| [AESTUS](https://aestus.live/) | Не регулируется | Только Hoodi | Все типы |
| [Titan Global](https://docs.titanrelay.xyz/) | Не регулируется | Только Hoodi | Все типы |

:::warning ПРИМЕЧАНИЕ
\*Релеи, соблюдающие санкции OFAC, следуют чёрному списку адресов, который ведёт Управление по контролю за иностранными активами США (OFAC).
Мы **настоятельно рекомендуем** подробнее изучить санкции OFAC и цензуру в сети и принять взвешенное решение о том, какие релеи вы готовы использовать.

Дополнительную информацию можно найти на [странице MEV](./mev#block-builders-и-relays).
:::

:::warning ВАЖНО
В mainnet Commit-Boost в Smart Node поддерживает **меньше релеев**, чем MEV-Boost. В частности, Commit-Boost в mainnet **не** включает:
- Ultra Sound (без фильтрации)
- Aestus
- Titan Global (без фильтрации)

Все релеи, доступные в Commit-Boost в mainnet, — это регулируемые/фильтрующие версии, соблюдающие санкции OFAC. Если вам нужен доступ к нерегулируемым релеям, продолжайте использовать MEV-Boost вместо Commit-Boost.
:::


## Награды и APY

Commit-Boost приносит награды, сопоставимые с MEV-Boost.
Поскольку в mainnet Commit-Boost поддерживает только регулируемые релеи, ваши награды MEV могут немного отличаться от MEV-Boost, если раньше вы использовали нерегулируемые релеи.

В будущем протоколы обязательств предлагающего, такие как предподтверждения и списки включения, могут приносить дополнительный доход сверх обычных наград MEV.

      - **Closed** (рекомендуется): API доступен только внутри сети Docker
      - **Open to Localhost**: API доступен на localhost
      - **Open to External hosts**: API доступен с внешних машин. Выбирайте этот вариант, только если вам нужен внешний доступ *и* вы выполнили необходимые шаги для защиты ноды от нежелательного трафика: [Securing Your Node](./securing-your-node)

## Проверка логов и работы

После включения Commit-Boost вы можете убедиться, что он работает правильно, проверив логи:

```bash
rocketpool service logs commit-boost
```

Вы должны увидеть вывод, похожий на этот, с успешными регистрациями валидаторов в релеях:

```

rocketpool_commit-boost  | 2026-05-21T03:06:11.587846Z  INFO : register validator successful method=/eth/v1/builder/validators req_id=dcbb5e96-709b-4e0f-b336-cca37eb81d6b
rocketpool_commit-boost  | 2026-05-21T03:06:11.587862Z  INFO : Responded with 200 OK in 548 ms method=/eth/v1/builder/validators req_id=dcbb5e96-709b-4e0f-b336-cca37eb81d6b
rocketpool_commit-boost  | 2026-05-21T03:12:35.037766Z  INFO : new request ua="nim-presto/0.0.3 (amd64/linux)" num_registrations=7 method=/eth/v1/builder/validators req_id=b47edad9-be4d-4a7f-b0d0-6c7ef4808629
rocketpool_commit-boost  | 2026-05-21T03:12:35.642706Z  INFO : register validator successful method=/eth/v1/builder/validators req_id=b47edad9-be4d-4a7f-b0d0-6c7ef4808629
rocketpool_commit-boost  | 2026-05-21T03:12:35.642721Z  INFO : Responded with 200 OK in 604 ms method=/eth/v1/builder/validators req_id=b47edad9-be4d-4a7f-b0d0-6c7ef4808629
```

На что обратить внимание в логах:
- Записи `new request`, показывающие, что ваш Validator Client подключается к Commit-Boost
- `register validator successful`, подтверждающие, что ваши валидаторы зарегистрированы в релеях
- Ответы `200 OK`, указывающие на успешное взаимодействие

Также можно проверить, что Commit-Boost запущен, командой:

```bash
rocketpool service version
```
Ближе к концу вывода вы должны увидеть:

```
MEV-Boost client: Disabled
Commit-Boost client: Enabled (Local Mode)
	Image: ghcr.io/commit-boost/commit-boost:<version>
```

Если вы используете внешне управляемый экземпляр, вместо этого будет показано `Enabled (External Mode)`.

## Переход с MEV-Boost на Commit-Boost

Перейти с MEV-Boost на Commit-Boost несложно:

1. Запустите `rocketpool service config`
2. Выберите категорию **ePBS**, затем **MEV-Boost**, и снимите флажок `Enable MEV-Boost`
3. Вернитесь в категорию **ePBS**, выберите **Commit-Boost** и отметьте `Enable Commit-Boost`
4. Настройте предпочтения по релеям
5. Сохраните изменения и выйдите

Остальное Smart Node сделает сам. Ваш Beacon Node будет автоматически перенастроен на использование Commit-Boost вместо MEV-Boost.

:::tip ПРИМЕЧАНИЕ
Переключение перезапускает ваш Beacon Node, поэтому ваши валидаторы могут пропустить одну-две аттестации, пока он снова запускается. Не переключайтесь непосредственно перед запланированным предложением блока.
:::
