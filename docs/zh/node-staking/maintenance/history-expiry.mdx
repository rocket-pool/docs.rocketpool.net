# 执行客户端历史过期

执行客户端可以删除旧的区块体和收据，从而将链数据保持在可管理的大小。Smartnode 的 **Pruning Mode**（修剪模式）设置（Execution Client → Pruning Mode）控制此行为。

**Rolling History Expiry**（滚动历史过期）是默认选项。Nethermind、Besu、Reth 和 Erigon 会删除大约一年以前的区块体和收据。Geth 尚未实现该模式，而是使用 Prague 之前的历史过期方式。

其他选项：

- **History Expiry** — 仅删除*合并前*的区块体和收据（部分 [EIP-4444](https://eips.ethereum.org/EIPS/eip-4444) 过期）。Erigon 不支持仅删除合并前历史。
- **Full node** — 保留常规的全节点数据，包括区块体和收据。Erigon 的全节点模式会保留收据。
- **Archive** — 保留历史记录和历史状态（这需要更多的磁盘空间）。

请随意阅读这篇关于部分历史过期的概述：https://blog.ethereum.org/2025/07/08/partial-history-exp

::: tip 注意

新安装的节点已经使用 Rolling History Expiry。如果您之前选择了其他修剪模式，请在 TUI 中选择 **Rolling History Expiry** 并**重新同步**执行客户端，使其生效。

- **Nethermind、Reth 和 Erigon** — 更改模式后需要重新同步（`rocketpool service resync-eth1`）。
- **Geth** — 使用 `rocketpool service prune-eth1` 修剪或重新同步；Geth 仍使用 Prague 之前的过期方式，而非一年期滚动过期。
- **Besu** — 保持在线。

:::

以下删除合并前历史的步骤仅适用于 Docker 模式节点。如果您在混合模式或原生模式下使用外部客户端，请参阅执行客户端提供的文档。

首先打开设置管理器：

```shell
rocketpool service config
```

要更改执行客户端修剪模式，请转到 `Execution Client (ETH1)` 菜单并在下拉菜单中为 `Pruning Mode` 选择 `History Expiry` 设置

除非您有理由保留更多历史记录，否则请选择 **Rolling History Expiry**。

![](../images/tui-history-expiry.png)

完成选择后，按 `escape` 返回主菜单，然后按 `tab` 突出显示 `Review Changes and Save` 按钮。按
`enter` 键继续。您将看到一个菜单来预览对执行客户端设置的更改。

![](../images/tui-review-history-expiry.png)

按 `Save Settings` 上的 `enter` 键保存并退出设置管理器，然后输入 `y` 重新启动您的 `rocketpool_eth1` 容器。

```shell
Your changes have been saved!
The following containers must be restarted for the changes to take effect:
	rocketpool_eth1
Would you like to restart them automatically now? [y/n]
```

从此时起，步骤因您使用的执行客户端而异：
