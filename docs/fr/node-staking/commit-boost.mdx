# Commit-Boost

Commit-Boost est un sidecar de validateur open source et porté par la communauté, qui sert d'alternative à MEV-Boost pour la séparation proposeur-constructeur (PBS).
En plus de la construction de blocs, Commit-Boost prend également en charge des protocoles d'engagements du proposeur, comme les préconfirmations et les listes d'inclusion.
Le Smart Node n'exécute actuellement que le module PBS (construction de blocs) de Commit-Boost, ces protocoles supplémentaires ne sont donc pas encore disponibles via le Smart Node.
Si vous découvrez le MEV et le PBS, nous vous recommandons de lire d'abord la page [MEV, MEV-Boost et Récompenses MEV](./mev) pour le contexte.

## Qu'est-ce que Commit-Boost ?

Commit-Boost est un remplaçant direct de MEV-Boost doté de fonctionnalités supplémentaires. Son objectif principal est de standardiser la communication entre les validateurs Ethereum et les protocoles tiers.

- Utilise la même Builder API que MEV-Boost (port par défaut 18550), votre Beacon Node communique donc avec lui de la même manière qu'avec MEV-Boost.
- Se connecte aux relais MEV et gère la construction de blocs, exactement comme MEV-Boost.
- Prend en charge un système de plugins modulaire pour les futurs protocoles d'engagements.
- Pour les développeurs, il fournit une API unique pour interagir avec les validateurs.

Commit-Boost est [open source](https://github.com/Commit-Boost/commit-boost-client) et a été [audité](https://github.com/Commit-Boost/commit-boost-client/blob/main/audit/Sigma_Prime_Commit_Boost_Client_Security_Assessment_Report_v2_0.pdf) par Sigma Prime en décembre 2024.

## Commit-Boost vs MEV-Boost

Commit-Boost et MEV-Boost gèrent tous deux le PBS en s'appuyant sur le marché des constructeurs et l'infrastructure des relais MEV. Voici leurs différences :

| Caractéristique | MEV-Boost | Commit-Boost |
|---------|-----------|--------------|
| **Objectif** | PBS uniquement | PBS + plateforme extensible et modulaire |
| **Mainteneur** | Flashbots | Communauté / équipe Commit-Boost |
| **Protocoles futurs** | Statique | Système de plugins pour protocoles tiers (pas encore disponible via le Smart Node) |
| **Relais disponibles (mainnet)** | 8 relais | 5 relais (filtrage OFAC uniquement) |

Du point de vue du Smart Node, les deux se connectent à votre Beacon Node de manière identique. Commit-Boost est tourné vers l'avenir, alors qu'Ethereum ajoute de nouvelles fonctionnalités d'engagements du proposeur comme les préconfirmations.

:::tip REMARQUE
Vous ne pouvez pas exécuter MEV-Boost et Commit-Boost en même temps. Le Smart Node l'impose lorsque vous enregistrez votre configuration dans le TUI.
:::

## Relais disponibles

Voici les relais disponibles dans Commit-Boost :

| Nom | Réglementation | Réseaux | Types de MEV |
|------|-----------|----------|-----------|
| [Flashbots](https://boost.flashbots.net/) | Conforme aux sanctions OFAC* | Mainnet, Hoodi | Tous types |
| [bloXroute Regulated](https://docs.bloxroute.com/eth/block-builders-and-validators/mev-relay-for-validators) | Conforme aux sanctions OFAC* | Mainnet, Hoodi | Tous types |
| [Titan Regional](https://docs.titanrelay.xyz/) | Conforme aux sanctions OFAC* | Mainnet uniquement | Tous types |
| [Ultra Sound Filtered](https://relay-filtered.ultrasound.money/) | Conforme aux sanctions OFAC* | Mainnet uniquement | Tous types |
| BTCS OFAC+ | Conforme aux sanctions OFAC* | Mainnet uniquement | Tous types |
| [AESTUS](https://aestus.live/) | Non réglementé | Hoodi uniquement | Tous types |
| [Titan Global](https://docs.titanrelay.xyz/) | Non réglementé | Hoodi uniquement | Tous types |

:::warning REMARQUE
\*Les relais conformes aux sanctions OFAC suivent la liste noire d'adresses tenue par l'Office of Foreign Assets Control (OFAC) des États-Unis.
Nous vous **encourageons vivement** à vous renseigner sur les sanctions OFAC et la censure du réseau, et à prendre une décision éclairée sur les relais que vous êtes prêt à utiliser.

Vous trouverez plus d'informations sur la [page MEV](./mev#constructeurs-de-blocs-et-relais).
:::

:::warning IMPORTANT
Sur le mainnet, Commit-Boost prend en charge **moins de relais** que MEV-Boost dans le Smart Node. Plus précisément, Commit-Boost sur le mainnet **n'inclut pas** :
- Ultra Sound (sans filtrage)
- Aestus
- Titan Global (sans filtrage)

Tous les relais disponibles dans Commit-Boost sur le mainnet sont des versions réglementées/filtrées conformes aux sanctions OFAC. Si vous avez besoin d'accéder à des relais non réglementés, vous devriez continuer à utiliser MEV-Boost plutôt que Commit-Boost.
:::


## Récompenses et APY

Commit-Boost offre des récompenses similaires à MEV-Boost.
Comme Commit-Boost ne prend en charge que des relais réglementés sur le mainnet, vos récompenses MEV peuvent différer légèrement de celles de MEV-Boost si vous utilisiez auparavant des relais non réglementés.

À l'avenir, des protocoles d'engagements du proposeur comme les préconfirmations et les listes d'inclusion pourraient ajouter un rendement supplémentaire aux récompenses MEV habituelles.

Les points clés à rechercher dans les logs :
- Des entrées `new request` montrant que votre Validator Client se connecte à Commit-Boost

Vous pouvez aussi vérifier que Commit-Boost tourne avec :

```bash
rocketpool service version
```
Vers la fin de la sortie, vous devriez voir :

```

Commit-Boost client: Enabled (Local Mode)
	Image: ghcr.io/commit-boost/commit-boost:<version>
```

Si vous utilisez une instance gérée en externe, `Enabled (External Mode)` s'affiche à la place.

## Passer de MEV-Boost à Commit-Boost

Passer de MEV-Boost à Commit-Boost est simple :

1. Exécutez `rocketpool service config`
2. Sélectionnez la catégorie **ePBS**, puis **MEV-Boost**, et décochez `Enable MEV-Boost`
3. Revenez à la catégorie **ePBS**, sélectionnez **Commit-Boost** et cochez `Enable Commit-Boost`
4. Configurez vos préférences de relais
5. Enregistrez et quittez

Le Smart Node s'occupe du reste. Votre Beacon Node sera automatiquement mis à jour pour utiliser Commit-Boost au lieu de MEV-Boost.

:::tip REMARQUE
Le changement redémarre votre Beacon Node, vos validateurs peuvent donc manquer une ou deux attestations le temps qu'il redémarre. Évitez de faire le changement juste avant une proposition prévue.
:::
