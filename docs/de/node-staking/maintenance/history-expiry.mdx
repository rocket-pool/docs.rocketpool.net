# Ablauf der Historie des Execution-Clients

Execution-Clients können alte Blockkörper und Belege verwerfen, damit die Chain-Daten eine handhabbare Größe behalten. Die Smartnode-Einstellung **Pruning Mode** (Execution Client → Pruning Mode) steuert dieses Verhalten.

**Rolling History Expiry** ist die Standardeinstellung. Nethermind, Besu, Reth und Erigon verwerfen Blockkörper und Belege, die älter als etwa ein Jahr sind. Geth implementiert diesen Modus noch nicht und verwendet stattdessen den Ablauf der Historie vor Prague.

Die anderen Optionen:

- **History Expiry** — verwirft ausschließlich _Pre-Merge_-Blockkörper und -Belege (teilweiser [EIP-4444](https://eips.ethereum.org/EIPS/eip-4444)-Ablauf). Erigon unterstützt keinen reinen Pre-Merge-Ablauf.
- **Full node** — behält die üblichen Full-Node-Daten einschließlich Blockkörper und Belege. Der Full-Node-Modus von Erigon behält die Belege.
- **Archive** — behält Historie und historischen Zustand (was deutlich mehr Speicherplatz erfordert).

Schauen Sie sich gerne diese Übersicht zum teilweisen Ablauf der Historie an: https://blog.ethereum.org/2025/07/08/partial-history-exp

::: tip HINWEIS

Neue Installationen verwenden bereits Rolling History Expiry. Wenn Sie zuvor einen anderen Pruning Mode gewählt haben, wählen Sie **Rolling History Expiry** im TUI und **synchronisieren Sie den Execution-Client neu**, damit die Änderung wirksam wird.

- **Nethermind, Reth und Erigon** — nach dem Ändern des Modus neu synchronisieren (`rocketpool service resync-eth1`).
- **Geth** — mit `rocketpool service prune-eth1` prunen oder neu synchronisieren; Geth verwendet weiterhin den Ablauf vor Prague statt des rollierenden Ein-Jahres-Ablaufs.
- **Besu** — bleibt online.

:::

Die folgenden Schritte zum Entfernen der Pre-Merge-Historie gelten nur für Nodes im Docker-Modus. Wenn Sie einen externen Client im Hybrid-Modus oder Native-Modus verwenden, beachten Sie bitte die von Ihrem Execution-Client bereitgestellte Dokumentation.

Öffnen Sie zunächst den Settings Manager:

```shell
rocketpool service config
```

Um den Pruning-Modus des Execution-Clients zu ändern, gehen Sie zum Menü `Execution Client (ETH1)` und wählen Sie im Dropdown-Menü für `Pruning Mode` die Einstellung `History Expiry` aus.

Wählen Sie **Rolling History Expiry**, sofern Sie keinen Grund haben, mehr Historie zu behalten.

![](../images/tui-history-expiry.png)

Nachdem Sie die Auswahl getroffen haben, drücken Sie `escape`, um zum Hauptmenü zurückzukehren, und drücken Sie dann `tab`, um die Schaltfläche `Review Changes and Save` hervorzuheben. Drücken Sie die `enter`-Taste, um fortzufahren. Ihnen wird ein Menü zur Vorschau der Änderungen an Ihren Execution-Client-Einstellungen angezeigt.

![](../images/tui-review-history-expiry.png)

Drücken Sie die `enter`-Taste auf `Save Settings`, um die Einstellungen zu speichern und den Settings Manager zu beenden, und geben Sie dann `y` ein, um Ihren `rocketpool_eth1`-Container neu zu starten.

```shell
Your changes have been saved!
The following containers must be restarted for the changes to take effect:
	rocketpool_eth1
Would you like to restart them automatically now? [y/n]
```

Von diesem Punkt an unterscheiden sich die Schritte je nachdem, welchen Execution-Client Sie verwenden:
