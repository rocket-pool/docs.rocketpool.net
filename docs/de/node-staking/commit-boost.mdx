# Commit-Boost

Commit-Boost ist ein quelloffener, von der Community getragener Validator-Sidecar, der als Alternative zu MEV-Boost für Proposer-Builder Separation (PBS) dient.
Neben dem Block Building unterstützt Commit-Boost auch Protokolle für Proposer Commitments, etwa Preconfirmations und Inclusion Lists.
Der Smart Node führt derzeit nur das PBS-Modul (Block Building) von Commit-Boost aus, daher sind diese zusätzlichen Protokolle über den Smart Node noch nicht verfügbar.
Wenn Sie neu bei MEV und PBS sind, empfehlen wir, zuerst die Seite [MEV, MEV-Boost & MEV-Belohnungen](./mev) als Hintergrund zu lesen.

## Was ist Commit-Boost?

Commit-Boost ist ein direkter Ersatz für MEV-Boost mit zusätzlichen Funktionen. Sein Hauptziel ist es, die Kommunikation zwischen Ethereum-Validatoren und Drittanbieter-Protokollen zu standardisieren.

- Verwendet dieselbe Builder API wie MEV-Boost (Standardport 18550), sodass Ihr Beacon Node mit ihm genauso kommuniziert wie mit MEV-Boost.
- Verbindet sich mit MEV-Relays und übernimmt das Block Building, genau wie MEV-Boost.
- Unterstützt ein modulares Plugin-System für kommende Commitment-Protokolle.
- Bietet Entwicklern eine einheitliche API für die Interaktion mit Validatoren.

Commit-Boost ist [Open Source](https://github.com/Commit-Boost/commit-boost-client) und wurde im Dezember 2024 von Sigma Prime [auditiert](https://github.com/Commit-Boost/commit-boost-client/blob/main/audit/Sigma_Prime_Commit_Boost_Client_Security_Assessment_Report_v2_0.pdf).

## Commit-Boost vs. MEV-Boost

Sowohl Commit-Boost als auch MEV-Boost wickeln PBS über den Builder-Marktplatz und die MEV-Relay-Infrastruktur ab. So unterscheiden sie sich:

| Merkmal                         | MEV-Boost | Commit-Boost                                                                          |
| ------------------------------- | --------- | ------------------------------------------------------------------------------------- |
| **Zweck**                       | Nur PBS   | PBS + erweiterbare, modulare Plattform                                                |
| **Maintainer**                  | Flashbots | Community / Commit-Boost-Team                                                         |
| **Zukünftige Protokolle**       | Statisch  | Plugin-System für Drittanbieter-Protokolle (über den Smart Node noch nicht verfügbar) |
| **Verfügbare Relays (Mainnet)** | 8 Relays  | 5 Relays (nur OFAC-filternd)                                                          |

Aus Sicht des Smart Node verbinden sich beide auf identische Weise mit Ihrem Beacon Node. Commit-Boost ist zukunftsorientiert, da Ethereum neue Proposer-Commitment-Funktionen wie Preconfirmations hinzufügt.

:::tip HINWEIS
Sie können MEV-Boost und Commit-Boost nicht gleichzeitig betreiben. Der Smart Node setzt dies beim Speichern Ihrer Konfiguration im TUI durch.
:::

## Verfügbare Relays

Diese Relays sind in Commit-Boost verfügbar:

| Name                                                                                                         | Regulierung                  | Netzwerke      | MEV-Typen  |
| ------------------------------------------------------------------------------------------------------------ | ---------------------------- | -------------- | ---------- |
| [Flashbots](https://boost.flashbots.net/)                                                                    | Entspricht OFAC-Sanktionen\* | Mainnet, Hoodi | Alle Typen |
| [bloXroute Regulated](https://docs.bloxroute.com/eth/block-builders-and-validators/mev-relay-for-validators) | Entspricht OFAC-Sanktionen\* | Mainnet, Hoodi | Alle Typen |
| [Titan Regional](https://docs.titanrelay.xyz/)                                                               | Entspricht OFAC-Sanktionen\* | Nur Mainnet    | Alle Typen |
| [Ultra Sound Filtered](https://relay-filtered.ultrasound.money/)                                             | Entspricht OFAC-Sanktionen\* | Nur Mainnet    | Alle Typen |
| BTCS OFAC+                                                                                                   | Entspricht OFAC-Sanktionen\* | Nur Mainnet    | Alle Typen |
| [AESTUS](https://aestus.live/)                                                                               | Unreguliert                  | Nur Hoodi      | Alle Typen |
| [Titan Global](https://docs.titanrelay.xyz/)                                                                 | Unreguliert                  | Nur Hoodi      | Alle Typen |

:::warning HINWEIS
\*Relays, die OFAC-Sanktionen entsprechen, folgen der Blacklist von Adressen, die das United States Office of Foreign Assets Control (OFAC) führt.
Wir **empfehlen dringend**, mehr über OFAC-Sanktionen und Netzwerkzensur zu lesen und eine sorgfältig informierte Entscheidung darüber zu treffen, welche Relays Sie verwenden möchten.

Weitere Informationen finden Sie auf der [MEV-Seite](./mev#block-builders-und-relays).
:::

:::warning WICHTIG
Im Mainnet unterstützt Commit-Boost im Smart Node **weniger Relays** als MEV-Boost. Konkret enthält Commit-Boost im Mainnet **nicht**:

- Ultra Sound (nicht filternd)
- Aestus
- Titan Global (nicht filternd)

Alle im Mainnet für Commit-Boost verfügbaren Relays sind regulierte/filternde Versionen, die OFAC-Sanktionen entsprechen. Wenn Sie Zugang zu unregulierten Relays benötigen, sollten Sie weiterhin MEV-Boost statt Commit-Boost verwenden.
:::

## Belohnungen und APY

Commit-Boost liefert ähnliche Belohnungen wie MEV-Boost.
Da Commit-Boost im Mainnet nur regulierte Relays unterstützt, können Ihre MEV-Belohnungen im Vergleich zu MEV-Boost leicht abweichen, wenn Sie zuvor unregulierte Relays verwendet haben.

In Zukunft könnten Proposer-Commitment-Protokolle wie Preconfirmations und Inclusion Lists zusätzliche Erträge zu den normalen MEV-Belohnungen beisteuern.

      **Expose API Port**:
      - **Closed** (empfohlen): Die API ist nur innerhalb des Docker-Netzwerks erreichbar
      - **Open to Localhost**: Die API ist über localhost erreichbar
      - **Open to External hosts**: Die API ist von externen Maschinen aus erreichbar. Wählen Sie dies nur, wenn Sie externen Zugriff benötigen *und* die richtigen Schritte befolgt haben, um Ihren Node vor unerwünschtem Datenverkehr zu schützen: [Securing Your Node](./securing-your-node)

      **Container Tag**: Das Docker-Image-Tag für Commit-Boost. Der Smart Node legt den Standardwert fest und aktualisiert ihn mit jedem Release. Sie können ihn manuell ändern, wenn eine neue Version erscheint, bevor der Smart Node aktualisiert wird.

## Logs prüfen und Funktion überprüfen

Nachdem Sie Commit-Boost aktiviert haben, können Sie anhand der Logs überprüfen, ob es korrekt läuft:

```bash
rocketpool service logs commit-boost
```


Worauf Sie in den Logs achten sollten:

- Einträge mit `new request`, die zeigen, dass sich Ihr Validator Client mit Commit-Boost verbindet
- `register validator successful`, was bestätigt, dass Ihre Validatoren bei den Relays registriert sind
- Antworten mit `200 OK`, die eine erfolgreiche Kommunikation anzeigen

Sie können auch mit folgendem Befehl überprüfen, ob Commit-Boost läuft:

```bash
rocketpool service version
```

Gegen Ende der Ausgabe sollten Sie Folgendes sehen:

```
MEV-Boost client: Disabled
Commit-Boost client: Enabled (Local Mode)
	Image: ghcr.io/commit-boost/commit-boost:<version>
```

Wenn Sie eine extern verwaltete Instanz verwenden, wird stattdessen `Enabled (External Mode)` angezeigt.

## Von MEV-Boost zu Commit-Boost wechseln

Der Wechsel von MEV-Boost zu Commit-Boost ist unkompliziert:

1. Führen Sie `rocketpool service config` aus
2. Wählen Sie die Kategorie **ePBS**, dann **MEV-Boost**, und deaktivieren Sie `Enable MEV-Boost`
3. Gehen Sie zurück zur Kategorie **ePBS**, wählen Sie **Commit-Boost** und aktivieren Sie `Enable Commit-Boost`
4. Konfigurieren Sie Ihre Relay-Einstellungen
5. Speichern und beenden Sie

Den Rest erledigt der Smart Node. Ihr Beacon Node wird automatisch so aktualisiert, dass er Commit-Boost statt MEV-Boost verwendet.

:::tip HINWEIS
Beim Wechsel wird Ihr Beacon Node neu gestartet, sodass Ihre Validatoren möglicherweise ein oder zwei Attestierungen verpassen, bis er wieder läuft. Wechseln Sie nicht kurz vor einem geplanten Proposal.
:::
