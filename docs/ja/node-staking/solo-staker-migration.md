# ソロステーキングからRocket Poolへの移行

::: danger ソロバリデーターの変換はできなくなりました
[Saturn 1アップグレード](/ja/upgrades/saturn-1/whats-new)により、既存のソロバリデーターを直接Rocket Poolバリデーターに変換する機能は廃止されました。
Minipool-ソロバリデーター変換を支えていた「vacant（空の）」minipoolを含む-は作成できなくなり、megapoolバリデーターは新規のBeacon Chainデポジットによってのみ作成できます。

ソロステーキングからRocket Poolにステークを移すには、現在は**ソロバリデーターを退出**させ、**megapoolの下で新しいバリデーターを作成**する必要があります。
このページでは、何が変わったのかを説明し、新しい手順をご案内します。
:::

## Saturn 1で変わったこと

Saturn 1以前は、ソロステーカーはBeacon Chainから退出することなく、アクティブなバリデーターをRocket Pool minipoolに変換できました。
そのプロセスは、特別な「vacant」minipoolを作成し、バリデーターの出金クレデンシャルを元の`0x00` BLSクレデンシャルからminipoolのアドレスに変更し、Oracle DAOのスクラブチェックを通過した後、minipoolを昇格（promote）させるというものでした。

Saturn 1アップグレードでは、新しいバリデーターを作成する方法としてminipoolが[megapool](/ja/node-staking/megapools/overview)に置き換えられ、ソロバリデーター変換は引き継がれませんでした：

- **Minipoolの作成はプロトコルレベルで無効化されており**、これにはvacant minipoolも含まれます。既存バリデーターの出金クレデンシャルの向き先にできるminipoolコントラクトはもう存在しません。
- **MegapoolバリデーターはRocket Poolデポジットキューを通じて作成され**、新規のBeacon Chainデポジットが必要です。まず1 ETHのプレステーク（prestake）を行い、プロトコルがバリデーターの出金クレデンシャルをオンチェーンで検証した後、残りの31 ETHをデポジットします。
  すでにアクティブなバリデーターはこのフローを通過できないため、既存のソロバリデーターをmegapoolに取り込む仕組みは存在しません。
- 変換に使用されていたSmartnodeコマンド（`rocketpool node create-vacant-minipool`や`rocketpool minipool promote`など）はCLIから削除されました。

要するに、現在ソロステーキングから移行する唯一の方法は、**バリデーターをBeacon Chainから退出させ、引き出したETHで新しいmegapoolバリデーターを作成する**ことです。

## なぜ移行するのか？

移行は誰にでも向いているわけではありませんが、Rocket Poolのmegapoolバリデーターには、従来のソロステーキングバリデーターに比べていくつかの利点があります：

- プールステーカーから借りたETHの部分（バリデーターごとに28 ETH）に対して**コミッションを獲得**できます。
- 既存の32 ETHのステークで、最大**8つのmegapoolバリデーター**を作成できます（現在のボンド額は各4 ETH）。最大224 ETHの借入ETHに対してコミッションを得られます。
- [Smoothing Pool](/ja/node-staking/fee-distrib-sp#the-smoothing-pool)への参加資格があります。Smoothing Poolは、すべての実行レイヤー報酬（ブロック提案や[MEV報酬](/ja/node-staking/mev)など）をプールし、各報酬インターバルで参加者に公平に分配します。
- MegapoolにRPLをステークすると、RPLインフレーション報酬に加えて[Voter Share報酬](/ja/node-staking/megapools/staking-and-claiming-rewards#how-voter-share-is-distributed-to-megapool-rpl-stakers)（プロトコルのETH収益の一部）を獲得でき、[pDAOガバナンス](/ja/pdao/overview)での投票権も得られます。RPLステーキングは完全に任意です。

とはいえ、強調しておくべき重要な違いもあります：

- プロトコルは一連のスマートコントラクトとして実装されているため、**スマートコントラクトリスク**を受け入れる必要があります。
- 従来のノード運用は**Smartnodeスタック**を利用します。そのソフトウェアをノードにインストールして実行することに伴うリスクを受け入れる必要があります。
- ノードオペレーターになるには新しい概念をいくつか学ぶ必要があるため、**学習コスト**が伴います。
- Megapoolバリデーターは報酬をプールステーカーと分け合うため、バリデーターの出金アドレスは実行レイヤー上のmegapoolコントラクトとなり、**自分が管理するEOAではありません**。これは実行レイヤー報酬の**フィー受取先（fee recipient）**にも当てはまります。
- **移行中の資金は何も生み出しません。** ソロバリデーターの退出からmegapoolバリデーターのアクティブ化までの間、報酬は得られません。新しいmegapoolバリデーターはアテステーションを開始する前に、Rocket PoolデポジットキューとBeacon Chainキューの*両方*を通過する必要があります。退出する前に、必ず下記の**タイミングに関する考慮事項**セクションをお読みください。

移行を決断する前に、これらの長所と短所を慎重に検討することをお勧めします。
プロセスを進めたい場合は、以下の手順をご覧ください。

## ステップ1：ソロバリデーターを退出させる

最初のステップは、ソロバリデーターをBeacon Chainから退出させ、残高を引き出すことです：

1. バリデーターがまだ`0x00` BLS出金クレデンシャルを使用している場合は、まず自分が管理するアドレスを指す[実行レイヤーの出金クレデンシャルに更新](https://launchpad.ethereum.org/en/withdrawals)する必要があります。これを行わないと、退出後にETHを引き出せません。
1. バリデーターの**自発的退出（voluntary exit）**を提出します。コンセンサス／バリデータークライアントで実行できます。詳細は使用しているクライアントのドキュメントを参照してください。
1. バリデーターがBeacon Chainの退出キューを通過し、全残高が出金アドレスに送られるまで待ちます。

::: warning 警告
自発的退出は**取り消せません**。一度退出したバリデーターは二度とバリデーションを行えません-戻る唯一の方法は新しいバリデーターを作成することです。
退出する前に、このページ全体（特に下記の**タイミングに関する考慮事項**セクション）を必ずお読みください。
:::

[validatorqueue.com](https://www.validatorqueue.com/)は、現在のBeacon Chain退出キューの長さを確認できる便利なサイトです。

## ステップ2：Rocket Poolノードをセットアップする

退出処理を待つ間に、Rocket Poolノードの準備を進められます。

Rocket Poolのノード運用が初めての場合は、[ノードオペレーターガイド](/ja/node-staking/responsibilities)から始めてください。ハードウェアの選定から[Smartnodeスタックのインストール](/ja/node-staking/installing/overview)、[ノードの登録](/ja/node-staking/prepare-node)まですべてをカバーしています。
これまで自分のバリデーターを運用してきた方なら、多くの内容が馴染み深く感じられるでしょう。すでに独自の実行クライアントとコンセンサスクライアントを運用している場合は、[外部クライアントを使用するハイブリッド構成](/ja/node-staking/install-modes#the-hybrid-configuration-with-external-clients)も参考になるはずです。

## ステップ3：Megapoolバリデーターを作成する

引き出したETHが手元に届いたら、`rocketpool megapool deposit`を使ってmegapoolバリデーターを作成できます。
現在、各バリデーターには**4 ETHのボンド**が必要で、ステーキングプールから**28 ETH**を借り入れます。つまり、引き出した32 ETHのステークで最大**8つのmegapoolバリデーター**を作成できます。
Megapoolコントラクトは最初のバリデーターデポジット時に自動的にデプロイされ、その後作成するすべてのバリデーターは同じmegapoolによって管理されます。

[Megapool（バリデーター）の作成](/ja/node-staking/megapools/create-megapool-validator)ガイドでは、デポジットキューの仕組みやステークの成功確認など、プロセス全体をステップバイステップで解説しています。

::: tip 注意
旧来の変換プロセスとは異なり、新しいバリデーターはSmartnodeウォレットから生成された**新しいバリデーターキー**を使用します。
古いソロバリデーターのキーは再利用されず、SmartnodeのValidator Clientが新しいキーを管理します-キーのインポート手順はもうありません。
:::

## タイミングに関する考慮事項

旧来の変換プロセスにはダウンタイムがなく、バリデーターは全期間を通じてアテステーションを継続していました。
新しい移行パスにはダウンタイムが伴うため、ソロバリデーターを退出させる前に、関係するキューを理解しておく価値があります：

1. **Beacon Chain退出キュー**：ソロバリデーターがどれだけ早く退出・出金できるかを決定します。
1. **Rocket Poolデポジットキュー**：新しいバリデーターがデポジットプールからの借入ETHとマッチングされるタイミングを決定します。エクスプレスキューのチケットは、レガシーminipoolにボンドされたETHに基づいて既存のノードオペレーターに配布されました。新しいノードは現在チケットを受け取れないため、元ソロステーカーのバリデーターは**標準キュー**に入ります。
1. **Beacon Chainデポジットキュー**：megapoolバリデーターはこれを**2回**通過します。1回目は1 ETHのプレステーク、2回目はプロトコルがバリデーターの出金クレデンシャルを検証した後の残り31 ETHのステークです。

ソロバリデーターが退出した瞬間からmegapoolバリデーターがアクティブ化されるまで報酬は得られないため、コミットする前にキューの状況を確認してください。

::: tip 有用なリンク
[validatorqueue.com](https://www.validatorqueue.com/)は、Beacon Chainキューの長さを確認できる便利なサイトです。このキューはBeacon Chainに出入りするETHの量に左右されます。
:::

デポジットキューが想定より長い場合は、ETHが割り当てられる前であればいつでも[バリデーターをRocket Poolデポジットキューから退出](/ja/node-staking/megapools/create-megapool-validator#exit-a-validator-from-the-rocket-pool-deposit-queue)させ、ボンドを[デポジットクレジット](/ja/node-staking/megapools/credit)として受け取ることができます。このクレジットはrETHと交換可能です。

## 代替案：ノードを運用せずにステーキングする

長所と短所を検討した結果、ノードを運用したくない場合は、引き出したETHをRocket Poolのリキッドステーキングトークンである[rETH](/ja/liquid-staking/overview)でステークするだけで、ハードウェアもメンテナンスもキューの待機も不要でステーキング報酬を得られます。
