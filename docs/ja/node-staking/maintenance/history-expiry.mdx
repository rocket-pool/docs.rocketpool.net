# Execution clientの履歴削除

Execution clientは古いブロックボディとレシートを破棄することで、チェーンデータを扱いやすいサイズに保つことができます。これはSmartnodeの**Pruning Mode**設定（Execution Client → Pruning Mode）で制御します。

**Rolling History Expiry**がデフォルトです。Nethermind、Besu、Reth、Erigonは、約1年より古いボディとレシートを破棄します。Gethはまだこのモードを実装しておらず、代わりにPrague以前の履歴削除を使用します。

その他の選択肢:

- **History Expiry** — *マージ前*のボディとレシートのみを破棄します（部分的な[EIP-4444](https://eips.ethereum.org/EIPS/eip-4444)削除）。Erigonはマージ前のみの削除には対応していません。
- **Full node** — ボディとレシートを含む通常のフルノードデータを保持します。Erigonのフルノードモードはレシートを保持します。
- **Archive** — 履歴と履歴ステートを保持します（大幅に多くのディスク容量が必要です）。

部分履歴削除の概要については、こちらをご覧ください: https://blog.ethereum.org/2025/07/08/partial-history-exp

::: tip 注意

新規インストールではすでにRolling History Expiryが使用されています。以前に別のPruning Modeを選択していた場合は、TUIで**Rolling History Expiry**を選択し、Execution clientを**再同期**して反映させてください。

- **Nethermind、Reth、Erigon** — モード変更後に再同期してください（`rocketpool service resync-eth1`）。
- **Geth** — `rocketpool service prune-eth1`でプルーニングするか再同期してください。Gethは1年のローリング削除ではなく、引き続きPrague以前の削除を使用します。
- **Besu** — オンラインのままです。

:::

マージ前履歴を削除する以下の手順は、Dockerモードのノードのみのものです。HybridモードまたはNativeモードで外部クライアントを使用している場合は、Execution clientが提供するドキュメントを参照してください。

まず、設定マネージャーを開きます:

```shell
rocketpool service config
```

Execution Clientのプルーニングモードを変更するには、`Execution Client (ETH1)`メニューに移動し、`Pruning Mode`のドロップダウンメニューで`History Expiry`設定を選択します

より多くの履歴を保持する理由がない限り、**Rolling History Expiry**を選択してください。

![](../images/tui-history-expiry.png)

選択後、`escape`を押してメインメニューに戻り、`tab`を押して`Review Changes and Save`ボタンをハイライトします。`enter`キーを押して続行します。Execution clientの設定変更をプレビューするメニューが表示されます。

![](../images/tui-review-history-expiry.png)

`Save Settings`で`enter`キーを押して設定を保存し、設定マネージャーを終了します。次に`y`を入力して`rocketpool_eth1`コンテナを再起動します。

```shell
Your changes have been saved!
The following containers must be restarted for the changes to take effect:
	rocketpool_eth1
Would you like to restart them automatically now? [y/n]
```

この時点から、使用しているExecution clientによって手順が異なります:
